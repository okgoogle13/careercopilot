## Decision Trees

### "I need to implement typography for my design system"

```
├─ Are you starting from scratch?
│  └─ YES → Use brand-brief-optimizer first (clarify brief)
│             Then choose base: M3 Expressive or kerala-rage kr-solidarity
│
├─ Do you need M3 Expressive?
│  ├─ YES → Start: m3-expressive-typography-enhancer (strategy)
│  │         Then: expressive-typography-manipulation (implement)
│  │         Then: m3-anti-slop-validator (validate)
│  │
│  └─ NO → Goto kerala-rage...
│
   │
172: └─ Do you need Kerala Rage?
173:    ├─ YES → Start: kerala-rage-typography-strategy (Solidarity, Agit-Prop)
174:    │         Then: expressive-typography-manipulation (Viscous Fluidity)
175:    │         Then: kerala-rage-visual-audit (validate)
176:    │
177:    └─ NO → Use design-token-validator (validate token structure)
```

### "I need to validate component design"

```
├─ Do you have a screenshot?
│  ├─ YES → Which standard?
│  │         ├─ M3 Expressive → m3-visual-audit
│  │         ├─ kerala-rage kr-solidarity → kerala-rage-visual-audit
│  │         └─ Generic quality → m3-anti-slop-validator
│  │
│  └─ NO → Is it a design mockup?
│           ├─ YES → ui-design-evaluator
│           └─ NO → Create mockup first with figma-to-page or m3-expressive-ui-evaluator
│
└─ Need compliance tracking?
   └─ YES → compliance-dashboard (kerala-rage) or m3-expressive-compliance-dashboard (M3)
```

### "I need to scaffold a React component"

```
├─ Do you have a wireframe?
│  ├─ YES (annotated) → wireframe-annotator → component-spec-generator → build manually
│  ├─ YES (Figma) → figma-to-page (if full page) or ui-design-evaluator → mockup → specs
│  └─ NO → Describe in brief → ui-design-evaluator → generate mockup → specs
│
└─ Need Storybook integration?
   └─ YES → storybook-scaffolder (after component exists)
```
