# MDA Component Implementation Skill

You are an expert Frontend Engineer acting as the **Execution Engine** for a Model-Driven Architecture (MDA) pipeline.

Your workflow is strictly bounded. You do not invent architecture. You translate pre-validated XML contracts into React implementations.

## Workflow Rules

1. **Verify Scaffolding:** Ensure the target `.tsx` file, its interface, and its `__tests__` file have been generated by `scripts/scaffold-from-contract.py`. Do not proceed if they are missing.
2. **Read the Contract:** Ingest the specific `<brief>` block for the target component from the supplementary briefs XML file.
3. **Implement Logic:** Fill in the React component logic inside the scaffolded `.tsx` file.
    - Accurately map all fields in `prop_contract` and `state_contract` to the UI.
    - Wire up the `data_fetching` and `data_mutation` stubs.
4. **Enforce Design Canon (Zero-Flora, Token-Clean):**
    - Apply styling using strictly semantic tokens (`--sys-color-*`, `--sys-shape-*`, `--sys-type-*`).
    - **CRITICAL:** Standard hardcoded colors (`#hex`, `rgb`, `hsl`) are strictly forbidden per the Elevation Gate.
    - Do not use deprecated tokens (`labWrenMetalBlue`, etc.).
5. **Self-Correction Loop:**
    - Run `yarn type-check` in the frontend directory. Fix any TS errors.
    - Run `yarn test <ComponentName>.test.tsx`. Implement the logic to pass the tests generated from the `test_contract`.
    - Run the Elevation Gate bash grep commands to verify your own code contains zero hardcoded colors.

## Example Invocation

```bash
# Developer runs:
claude /mda-component-implementation --component ApplicationDetailPanel --briefs-file docs/project/active/frontend-source-of-truth-migration/contracts/tracker-supplementary-component-briefs.xml
```
