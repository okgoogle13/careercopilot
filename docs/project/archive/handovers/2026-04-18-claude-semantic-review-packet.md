**Owner:** Claude Code
**Execution venue:** External Claude Code session
**Coordinator:** Codex
**Batch:** Batch 1, token translation and inventory

## Goal

Review the candidate token mappings generated by the inventory pass and approve, correct, or qualify them where semantic intent is ambiguous.

This is review-only work. Do not implement code changes.

## Decision Scope

Claude Code is being asked to make semantic judgments where donor naming, archive naming, and runtime KR naming do not align mechanically.

You are not being asked to:
- edit files
- perform broad refactors
- change route exposure
- promote donor code into runtime truth

Use this order to resolve disagreements:

7. runtime truth under `frontend/src/**`

Special rules:
- Canon wins for palette, typography, shape vocabulary, and flora bans.
- Donor code is reference material, not implementation truth.
- Phase3 donor-reference files are closer to current migration intent than archive donor exports.
- When archive donor names encode vague UI semantics like “surface” or “on-surface,” prefer mapping by usage intent, not by lexical similarity.

## Questions To Answer

1. Which candidate mappings are approved as-is?
2. Which candidate mappings need contextual qualification?
3. Which mappings should explicitly vary by usage context, such as:
- body text
- poster/high-contrast headline text
- border/divider use
- background/elevation use
4. Which archive-era semantics should never be translated mechanically and instead require file-by-file judgment?
5. Are any of the candidate mappings inconsistent with KR canon?

## Output Format

Return a memo with these sections:

### 1. Approved Mappings
- exact source -> target mapping lines

### 2. Conditional Mappings
- source name
- allowed target options
- rule for choosing between them

### 3. Non-Mechanical Cases
- names or families that must not be bulk-replaced
- short reason

### 4. Canon Risks
- any mapping that could violate KR canon, typography policy, or token semantics

### 5. Final Recommendation
- short recommendation on what Codex should allow `Claude Code` to do mechanically vs what must stay under Codex review

## Constraints

- Review only
- Do not implement
- Do not propose new token namespaces
- Do not normalize archive donor code into production truth
- If uncertain, prefer “conditional mapping” over false precision
