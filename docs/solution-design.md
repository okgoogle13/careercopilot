# Solution Design Document: CareerCopilot

## 1. High-Level Architecture

The CareerCopilot application is built on a **distributed, service-oriented architecture (SOA)**. This architecture is composed of several loosely coupled services that work together to provide the application's functionality. This design allows for scalability, flexibility, and independent development and deployment of each component.

The main components are:

- **Frontend:** A single-page application (SPA) built with React, responsible for the user interface and user experience.
- **Backend:** A core API service built with Python and FastAPI, which handles business logic, data processing, and communication with other services.
- **Serverless Functions:** A set of Firebase Functions for specific, event-driven, or background tasks.
- **Database:** A primary relational database for storing core application data, and Firestore for other data needs.
- **AI/ML Services:** Integration with external AI/ML models (like Anthropic's Claude and Google's Genkit) for advanced features.

### Architecture Diagram

```
[User] -> [Frontend (React SPA)]
    |
    v
[Backend (FastAPI)] -> [Database (PostgreSQL/SQLite)]
    |
    +-> [Firebase (Functions, Firestore, Storage)]
    |
    +-> [AI/ML Services (Genkit, Claude)]
    |
    +-> [AWS SES (Email)]
```

## 3. Data Model

The primary data model is defined using SQLAlchemy and managed through Alembic migrations. The core database tables include:

- **users:** Stores user information, including email, name, and profile details.
- **jobs:** Contains information about job opportunities that users are tracking.
- **applications:** Tracks the status of a user's application for a specific job.
- **ai_interactions:** Logs interactions with AI services, including prompts, responses, and performance metrics.
- **cache:** A caching table for storing results of expensive operations.
- **market_analysis:** Stores results of market analysis tasks.

### Initial Schema (from migration `39448280638b`)

- **users:**
  - `id` (String, PK)
  - `email` (String, Unique)
  - `name` (String)
  - `created_at` (DateTime)
  - `updated_at` (DateTime)
  - ... and other profile fields
- **jobs:**
  - `id` (String, PK)
  - `user_id` (String, FK to users.id)
  - `title` (String)
  - `company` (String)
  - `description` (Text)
  - ... and other job details
- **applications:**
  - `id` (String, PK)
  - `user_id` (String, FK to users.id)
  - `job_id` (String, FK to jobs.id)
  - `status` (String)
  - `applied_at` (DateTime)
  - ... and other application tracking fields

## 4. API Contracts

The backend API is built with FastAPI, which automatically generates OpenAPI documentation. The API is versioned and follows RESTful principles.

### Router Structure

The main API router is located in `backend/app/api/router.py` and includes the following sub-routers:

- `/auth`: Handles user authentication (registration, login, logout, token refresh).
- `/analysis`: Provides access to AI-powered analysis features (e.g., ATS score, job matching).
- `/config`: For client-side configuration needs.
- `/workflows`: To trigger and manage backend workflows.

### Example Endpoints

#### Authentication (`/auth`)

- **`POST /auth/register`**: Registers a new user.
  - **Request Body:** `UserRegistrationRequest` (email, name, password)
  - **Response Body:** `UserRegistrationResponse` (user_id, email, name, access_token)
- **`POST /auth/login`**: Authenticates a user.
  - **Request Body:** `UserLoginRequest` (email, password)
  - **Response Body:** `UserLoginResponse` (user_id, email, name, access_token)
- **`GET /auth/me`**: Retrieves the current authenticated user's information.

#### Analysis (`/analysis`)

- **`POST /analysis/ats-score`**: Calculates an Applicant Tracking System (ATS) score for a resume against a job description.
  - **Request Body:** `ATSScoreRequest` (resume_text, job_description)
  - **Response Body:** `ATSScoreResponse` (overallScore, categories, matched_keywords, missing_keywords)
- **`POST /analysis/job-matching`**: Analyzes the compatibility between a candidate's profile and a job description.

The Pydantic models in `backend/app/models/schemas.py` define the exact structure of the request and response bodies for each endpoint.

## 5. Key Dependencies and Integrations

### Internal Dependencies

- **Frontend -> Backend:** The frontend communicates with the backend via RESTful API calls.
- **Backend -> Firebase:** The backend uses Firebase for authentication, Firestore, and Storage.
- **Backend -> Serverless Functions:** The backend can trigger Firebase Functions for specific tasks.

### External Integrations

- **Google Genkit:** Used as a framework for building and orchestrating AI flows.
- **Anthropic Claude:** Integrated as one of the primary large language models (LLMs) for content generation and analysis.
- **OpenAI:** Also available as an LLM provider.
- **AWS Simple Email Service (SES):** Used for sending transactional emails (e.g., application confirmations, notifications).
- **Firebase Authentication:** Handles user identity and authentication.
- **Google Cloud Secret Manager:** For securely storing and managing API keys and other secrets.
