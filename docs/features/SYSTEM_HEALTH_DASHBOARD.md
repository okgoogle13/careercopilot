## Summary

Build a Quick Win System Health Dashboard to provide centralized visibility into application health, API status, test results, and recent errors.

## Business Value

- **Development Efficiency:** Save 2-4 hours/week on debugging
- **System Reliability:** Catch issues before users report them
- **Team Collaboration:** Shared visibility into system state
- **ROI Score:** 7.8/10

## Requirements

### Functional

1. **System Status Panel**
   - Green/Yellow/Red indicators for API health
   - Service uptime display
   - Last deployment timestamp

2. **Quick Stats**
   - Frontend test pass rate
   - Backend test pass rate
   - E2E test status
   - Error count (last 24 hours)

3. **Recent Events**
   - Last 10 errors from logs
   - Recent test failures
   - Deployment history

4. **Auto-Refresh**
   - Poll every 30 seconds
   - Manual refresh button

### Technical

#### Backend
- **New File:** `backend/app/api/system_health.py`
- **New Service:** `backend/app/services/health_service.py`
- **Endpoint:** `GET /api/v1/system-health`
- **Response:**
  ```json
  {
    "status": "healthy|degraded|critical",
    "apis": {...},
    "tests": {...},
    "errors": {...},
    "timestamp": "..."
  }
  ```

#### Frontend
- **New Page:** `frontend/src/features/admin/SystemHealth.tsx`
- **New Components:**
  - `StatusCard.tsx` - Health indicator cards
  - `RecentErrorsList.tsx` - Error list component
- **Route:** `/admin/system-health`
- **Access:** Protected route, works with `?demo=true`

### Non-Functional

- **Performance:** Dashboard loads in < 2s
- **Reliability:** 30s polling doesn't impact app performance
- **Accessibility:** WCAG AA compliant
- **M3 Compliance:** Uses [DEPRECATED_STYLE] shapes and elevation
