## 🎨 **Quick Reference: Electric Alchemist**

```css

.rounded-pebble   → 16px                (Interactive, Buttons)
.rounded-tech     → 12px                (Inputs, Containers)
```

### **Starting Development**
```bash
cd frontend && yarn dev
```
→ See: PROJECT_ARCHITECTURE.md → Build & Deploy

### **Creating New Component**
1. Check ELECTRIC_ALCHEMIST_V5.md → Component Patterns
2. Use M3 shape tokens (rounded-leaf, rounded-pebble, rounded-tech)
3. Apply semantic color tokens (text-primary, bg-surface-container)
4. Validate with Anti-Slop checklist

### **Debugging Intelligence**
1. Review EXPERT_RESUME_AUDITOR.md → 4-Quadrant Logic
2. Check `hooks/useAnalysis.ts` implementation
3. Inspect AI prompt in `services/prompts.ts`
4. Test with INTELLIGENCE_WALKTHROUGH.md steps

### **Verifying Design Compliance**
1. Open ELECTRIC_ALCHEMIST_V5.md → Anti-Slop Validation
2. Check:
   - ❌ No `rounded-full` on non-circular elements
   - ❌ No hardcoded hex colors
   - ❌ No inline `style={{...}}`
   - ✅ All M3 tokens applied

## 🎯 **Project Philosophy**

### **Design Principles**
1. **Function + Delight** - Every element serves both purposes
2. **M3 Expressive** - No generic Material Design
3. **Chromebook-Safe** - CSS-only effects, transform animations
4. **Anti-Slop** - Rigorous validation against AI-generated mediocrity

### **Intelligence Principles**
1. **4-Quadrant Transparency** - Users see exactly what's measured
2. **Contextual Why** - Every suggestion explains its strategic value
3. **Google XYZ Formula** - Evidence-based quantification standard
4. **APS ILS Standards** - Australian Public Service frameworks

### **Code Principles**
1. **TypeScript Strict** - No implicit any
2. **M3 Tokens Only** - No hardcoded values
3. **Semantic Naming** - Self-documenting code
4. **Performance First** - Chromebook-optimized
