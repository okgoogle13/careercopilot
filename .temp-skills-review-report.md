## Skill 1: storybook-scaffolder

### Overview

**Purpose:** Generate Storybook story files (`*.stories.tsx`) with M3 design token imports and interactive variant stories.

**Version:** 2.0 (simplified workflow)

**Complexity:** LOW (4-step process)

---

### Fit for Purpose Analysis

#### ✅ Strengths

1. **Simple Template-Based Generation**
   - Uses clean template (`story.tsx.tpl`)
   - Minimal placeholders: `{{COMPONENT_NAME}}`, `{{COMPONENT_PATH}}`, `{{STORY_TITLE}}`
   - Auto-imports design tokens CSS

2. **Already Proven in Codebase**
   - 46 existing `.stories.tsx` files found
   - Existing stories for gold standard components:
     - ✅ ActionButton.stories.tsx
     - ✅ SolidarityCard.stories.tsx
     - ✅ ManifestoSlab.stories.tsx
     - ✅ Stone.stories.tsx (needs update)

3. **Alignment with Migration Needs**
   - Perfect for documenting newly migrated components
   - Prepends `import 'src/styles/design-tokens.css'` automatically
   - Includes `['autodocs']` tag for automatic prop documentation

#### ⚠️ Limitations

1. **Template is Minimal**
   - Generates skeleton only (`// TODO: Add default args`)
   - Requires manual prop population
   - No variant-specific story examples

2. **No Archetype-Specific Templates**
   - Doesn't know about Seed, Jar, Cabinet, etc.
   - Can't auto-generate archetype-appropriate variants
   - Generic template for all component types

3. **Existing Stories Need Updates**
   - Stone.stories.tsx still has `mode` prop (deprecated)
   - No automated way to update existing stories

## Skill Improvement Recommendations

### storybook-scaffolder Enhancements

**Priority:** MEDIUM (current template is functional)

#### 1. Archetype-Aware Templates

Create variant templates for each archetype:

```
templates/
  seed.stories.tsx.tpl       # Buttons, chips
  jar.stories.tsx.tpl        # Cards, containers
  cabinet.stories.tsx.tpl    # Complex layouts
  lens.stories.tsx.tpl       # Inputs, modals
  stone.stories.tsx.tpl      # Structural dividers
```

**Benefit:** Auto-generate appropriate variants for each archetype

#### 2. Prop Inference

Parse component TypeScript interface to pre-populate args:

```typescript
// Auto-detect from ActionButtonProps
export const Primary: Story = {
  args: {
    variant: 'primary',  // ← inferred from type definition
    label: 'Button',      // ← inferred from type definition
    size: 'md',          // ← inferred with default
  },
};
```

**Benefit:** Reduce manual TODO completion

#### 3. Accessibility Story Generation

Auto-add accessibility-focused stories:

```typescript
export const KeyboardNavigation: Story = {
  args: { ...Primary.args },
  play: async ({ canvasElement }) => {
    // Auto-test Tab, Enter, Space
  },
};
```

**Benefit:** Built-in a11y testing
